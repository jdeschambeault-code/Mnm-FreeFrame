# Every package below is pinned to an exact version - including transitive
# ones that nothing above declares directly. This is deliberate, not
# cosmetic: `uv pip install -r requirements.txt` re-resolves "whatever's
# newest and still satisfies every constraint" for anything left unpinned,
# EVERY time it runs - not once and cached. Two installs from this exact
# file, run hours apart or on two different machines, can legitimately
# resolve different transitive versions. That's not hypothetical - it's
# exactly what happened here: one install resolved anyio 4.14.2 (paired
# with a typing_extensions missing the `sentinel` helper it needs, breaking
# uvicorn's startup import) while another, from the identical file, resolved
# anyio 4.15.1 and a typing_extensions that had it. Pinning typing_extensions
# alone fixed that one symptom; pinning *everything* here (frozen from a
# verified-working install, `uv pip freeze`) is what actually closes the
# whole class of "works on one machine, not the other" bug rather than
# chasing it package by package. When you deliberately want to move to
# newer versions, regenerate deliberately (`uv pip compile`/`uv pip freeze`
# against a fresh install you've tested) - don't just delete a pin.
